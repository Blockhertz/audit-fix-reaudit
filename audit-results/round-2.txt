  [31m[1m[CRITICAL][0m Unprotected drainFunds() allows anyone to steal all ETH
  The `drainFunds(address payable recipient)` function has no access control modifier, meaning any external address can call it and transfer the entire contract balance to an arbitrary recipient. This completely undermines the deposit/withdraw accounting system and allows instant, total loss of all user funds.
  [1mFix:[0m Add an `onlyOwner` modifier (or equivalent access control) to `drainFunds()`. Introduce an `owner` state variable set in the constructor and restrict sensitive administrative functions to that address. Alternatively, remove `drainFunds()` entirely if it serves no legitimate purpose.

  [36m[1m[MEDIUM][0m No event emissions for deposit, withdrawal, or drain actions
  None of the state-changing functions (`deposit`, `withdraw`, `drainFunds`) emit events. This makes it impossible to monitor or audit fund movements off-chain, hindering incident detection and forensic analysis.
  [1mFix:[0m Define and emit events such as `Deposit(address indexed user, uint256 amount)`, `Withdrawal(address indexed user, uint256 amount)`, and `Drain(address indexed recipient, uint256 amount)` in each respective function.

  [32m[1m[LOW][0m Use of transfer() instead of call() in drainFunds()
  `recipient.transfer(...)` forwards only 2300 gas, which can fail if the recipient is a contract with a non-trivial fallback function. While this is a secondary concern given the critical access control bug, it is still a best-practice violation that could cause unexpected reverts.
  [1mFix:[0m Replace `recipient.transfer(address(this).balance)` with a low-level call pattern: `(bool ok, ) = recipient.call{value: address(this).balance}(""); require(ok, "Transfer failed");` — after first fixing the access control issue.

  [32m[1m[LOW][0m Missing zero-amount check in withdraw()
  A user can call `withdraw(0)`, which passes the balance check, performs a no-op state update, and triggers an external call with zero value. While not directly exploitable, it wastes gas and may interact unexpectedly with recipient contracts.
  [1mFix:[0m Add `require(amount > 0, "Amount must be greater than zero");` at the start of the `withdraw` function.

  [32m[1m[LOW][0m No constructor or owner initialization

  [1mFix:[0m Add a constructor that sets an `owner` state variable: `address public owner; constructor() { owner = msg.sender; }` and use it to gate administrative functions.

  [35m[1m[GAS][0m getBalance() duplicates publicly available data

  [1mFix:[0m Remove `getBalance()` since callers can query `address(this).balance` directly or via `eth_getBalance` RPC calls, saving deployment gas.
